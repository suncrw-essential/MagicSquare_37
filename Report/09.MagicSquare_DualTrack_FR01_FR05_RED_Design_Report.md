## 2. SSOT 계약 요약

### 2.1 입력·출력

| 구분 | 규칙 |
|------|------|
| 입력 | `int[4][4]`; `0`=빈칸 **정확히 2개**; 값 ∈ `{0}∪{1..16}`; 0 제외 중복 금지 |
| 출력 | `int[6]` = `[r1,c1,n1,r2,c2,n2]`; 좌표 **1-index** |
| 마방진 상수 | 4×4 → **M = 34** (`MagicConstant` SSOT) |

### 2.2 Boundary 검증 순서 (short-circuit)

`null` → `size` → `empty count` → `value range` → `duplicate`

### 2.3 Boundary 오류 코드 (학습용 E00x)

| Code | 조건 | PRD §13 message (고정 문자열) |
|------|------|-------------------------------|
| E003 | `matrix == null` | `Grid must have exactly 4 rows.` |
| E001 | size ≠ 4×4 (행/열) | 행: `Grid must have exactly 4 rows.` / 열: `Each row must have exactly 4 columns.` |
| E002 | `0` 개수 ≠ 2 | `Grid must contain exactly 2 empty cells (0).` |
| E004 | 값 ∉ {0}∪[1,16] | `Cell values must be 0 or between 1 and 16 inclusive.` |
| E005 | 0 제외 중복 | `Non-zero values must be unique.` |

> **Decision Needed (OI-04):** PRD 공식 코드 `ERR_GRID_*` ↔ 학습용 `E00x` GREEN 전 통일.

### 2.4 Domain 흐름 격리

- invalid 입력 시 `SolvePartialMagicSquare.execute` **0회** (U-FLOW-02, FR-01 Error Policy).


**PLACEHOLDER** — Report/02 부록에 입력 격자 미기재. TS-N-02 / reverse 성공 격자는 GREEN 전 손검증 후 치환.

### G3 — Step A·B 모두 실패 (D-SOL-03)

**PLACEHOLDER** — DT-105 / TS-E-05 무해 격자. GREEN 전 손검증 후 치환. Domain: `UnsolvableDomainError` (Boundary: `ERR_NO_SOLUTION`).
